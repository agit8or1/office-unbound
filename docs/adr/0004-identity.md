# ADR-0004 Identity architecture
Status: Integrated in lab (2026-11-15) — OpenLDAP authoritative, Keycloak read-only federation, OpenCloud same LDAP read-only (identity-files-lab-results.md). Deprovisioning must revoke Keycloak sessions/offline tokens explicitly (measured).
Per customer stack: one LDAP directory as user/group source of truth (candidate lldap; OpenLDAP/389DS if OpenCloud/gromox schema needs require), federated into one Keycloak instance/realm for OIDC SSO + MFA. Gromox binds LDAP directly (ldap_adaptor cannot use Keycloak). OpenCloud uses Keycloak OIDC; user provisioning path (autoprovision vs. shared LDAP) decided by spike.
Provisioning is done by ICS/MSP API into LDAP, then reconciled downstream. Deprovisioning must revoke Keycloak sessions + offline tokens, gromox access, app passwords, ActiveSync devices; max delay to be measured (target ≤ 5 min).

## Groupware LDAP result (2026-11-15, lab)
Gromox 3.13 on `ou-gw1` authenticates against the same OpenLDAP as Keycloak/OpenCloud through `ldap_adaptor` (LDAPS, verified lab CA, dedicated read-only `svc-gromox` bind with an attribute/subtree-limited ACL). Gromox keeps its SQL `users` table as a lookup table; a directory user is "externally managed" when `externid` = LDAP `entryUUID`. Public Gromox has no LDAP importer (only admin-api does), so Office Unbound uses its own idempotent reconcile step (`gw-ldap-sync.py`, the future ICS `groupware.sync_users` action) instead of building admin-api; no licence-cap patch is needed. Measured (groupware-ldap-results.md): provision = LDAP add + reconcile (0.4 s) -> same password works on Keycloak, OpenCloud, IMAPS, EWS, ActiveSync, MAPI/HTTP and mail arrives; deprovision by LDAP lock alone is refused on all Gromox paths within 60 s (credential caches, tunable), with reconcile (suspend) ~0 s. Still required explicitly: Keycloak session/offline-token revoke, termination of already-open IMAP sessions (gromox-imap restart or idle timeout 30 min), and ActiveSync remote wipe, which must be requested before the account is suspended and needs an endpoint we do not have without admin-api (unproven). Legacy SQL-password lab users are kept in a separate domain, not migrated.

## Lifecycle implementation (2026-11-15, lab)
ICS actions `idm.*` (ics/README.md) drive LDAP (`cn=svc-ics`, narrow ACL) -> Keycloak (`ou-ics` service account: manage-users/view-users/query-clients) -> Gromox/OpenCloud (node-agent runbooks). Disable = LDAP lock + Keycloak disable/logout/consent-revoke + Gromox suspend + mailbox quarantine, followed by an active VERIFY that records seconds-to-refusal per credential path (measured <= 10 s in the lab, target 60 s). Not revocable per user: OpenCloud app tokens (refused only because the user no longer resolves; they come back on enable), ActiveSync remote wipe, open Gromox sessions other than IMAP. See `docs/status/user-lifecycle-results.md`.
