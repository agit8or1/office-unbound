## 2. What was proven, how

Fresh machine `ou-art1` (clone of `ou-base-noble`, MemoryMax 3G, 192.168.186.248; peak 1.73 GB of 3 GB with Keycloak + OpenCloud + PostgreSQL + slapd + nginx). Prepared with the REAL ICS cloud-init renderer (`ics.guest.cloudinit`, NoCloud seed, agent bundle from this branch, image key = dev channel key, pinned OU repo key = dev release key). Then:

1. `pkg.install_pinned` (exact versions above) -> `{"ok": true}` for slapd, ldap-utils, postgresql-16, nginx, inotify-tools. A bare `2.6.10` is refused by apt (see defect 2).
2. `podman.pull_verified` of both digests under the root-owned `sigstoreSigned` policy with the dev key -> `verified: true, policy: sigstoreSigned`. Negative controls on the same node: the same keycloak digest under another repository (`ou/unsignedprobe`, no signature attachment) -> `verified: false` ("A signature was required, but no signature exists"); a tag instead of a digest -> `bad_params`.
3. `podman.deploy_unit` for both (container-hostnet, rootless user `ou-svc`, read-only rootfs, all capabilities dropped, named volumes, podman secrets for passwords) -> `started: true, active_state: active`.
4. Health checks (`blueprints/build/oci/idfiles/art-health.sh`, 11/11 PASS, also after a full `machinectl reboot` of the machine: both units came back by themselves).
5. Lab suites run inside the machine against the stack (`blueprints/lab/tests`, unchanged): t01 36/0/0, t02 11/0/0 (with a restart hook through the user manager: data identical after an `opencloud` restart), t05 9/0/0, t06 14/2 (as the baseline).
   One run failed: the FIRST t02 run after the first start of OpenCloud returned `GET small.txt` HTTP 425 (posix storage still processing); the next 4 runs, including the one after the reboot, were 11/0/0. Evidence: `first-run-t02_files_webdav.out`. Treat as a cold-start race, not investigated further.
6. SBOM + OSV scan of each image made by the test runner itself (`ou-test-attest run oci-scan`, pinned syft + osv-scanner) and bound to the signature by the signer: Keycloak 5321 components / 118 vulnerability ids / max CVSS 9.8; OpenCloud 4473 components / 281 ids / max CVSS 9.8 (`*.sbom.cdx.json.gz`, `*.scan-attestation.json`). For the three distro packages: CycloneDX + OSV scan of the guest's whole dpkg set (318 packages, 301 ids, `guest-pkgs.*.gz`): `postgresql-16` has 52 Ubuntu CVE records against 16.15, `slapd` and `nginx` none, 60 for `openssl` in the base.
7. Licence record (from package metadata / SBOM): Keycloak Apache-2.0; OpenCloud Apache-2.0; OpenLDAP "OpenLDAP-2.8" (OpenLDAP Public License, permissive; counsel still to re-read, as in `third-party-inventory.md`); PostgreSQL "PostgreSQL" licence; nginx BSD-2-Clause. All zero licence cost. The SBOMs list the GPL/LGPL packages of the Ubuntu base layer (dynamic OS packages, not linked into the products).

## 3. Defects found and fixed on this branch

1. **`pkg.install_pinned` refused every distro package** (`release_channel_mismatch`, `noble-updates` has `Codename=noble`): the review-7 H-2 channel check was applied to all sources. Fixed in `ics/agent/ou_agent/guesthelper.py` (check only the Office Unbound repository line) + regression test `test_distro_suites_are_not_subject_to_the_channel_contract`. **Any branch that has the review-7 agent has this bug.**
2. **Catalog package pins were upstream versions** (`2.6.10`, `16.15`, `1.24.0`); the runbook needs the exact apt version. Fixed in the catalog.
3. **Plans carried no unit configuration**: `podman.deploy_unit` params were image + ports only, which cannot start Keycloak (database, hostname, secrets) or OpenCloud. New optional catalog block `unit:` (type, env with `{domain}`, named secrets, volumes, memory) on OCI artifacts, passed through by `_install_params`; a test checks that the plan output passes the agent's own closed schema (`guestspec.check_deploy`).
4. `blueprints/build/oci/oci-sign.sh` called the old attestation interface (v1, `ou-artifact-attest`); the installed hardened signer expects v2 (`ou-test-attest run oci-scan`). Client updated; signing works (`signed ... for channel dev`).
5. Images: Keycloak entrypoint now imports realms found in the data volume; OpenCloud image lacked `inotify-tools` (posix storage panics: `inotifywait is not installed`) and had no first-start `opencloud init`; both entrypoints read an optional rendered `KEY=VALUE` file (parsed, never evaluated) because the unit spec's env character class cannot carry LDAP filters. OpenCloud health check changed to `/status.php`. First builds (digests `aaa428f4...` Keycloak, `3d77d264...` / `21590bf4...` OpenCloud, tag `26.8.2` / `9.1.0` / `9.1.0-ou1`) belong to the oci-signing agent or were superseded; they stay valid and signed in the registry but are not the catalog pins.
6. `build-images.sh`: `OU_TAG_SUFFIX`, `IDW`, `OUT` so a rebuild never overwrites another agent's tags/contexts.
