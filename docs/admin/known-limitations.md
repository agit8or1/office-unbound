# Known limitations (0.10.0 "Juniper", alpha)

What not to promise yet. Updated 2026-11-23 for the alpha; each line says where it is tracked. Install steps: [Alpha install guide](alpha-install.md).

## Scope of what was proven
- **One reference installation.** Everything below "works" means: run on one ICS host, one Proxmox VE node (pve06) and one public IP, with
  one deployment at a time (officeunbound .. officeunbound7). Multi-node placement, several customers side by side on real Proxmox and
  network isolation between them (SDN) are not proven on real infrastructure (isolation is tested in the lab: [tenant-isolation-results.md](../status/tenant-isolation-results.md)).
- **No production data.** 0.x releases may change data formats and the deployment layout.

## Installing
- **Release artifacts are not downloadable yet.** The golden VM image and the `ou-*` packages are built and signed on the reference host
  (release signer, test runner and build machines). An outside installation can install the ICS from the tag but needs the project's help to
  get signed artifacts ([alpha-install.md](alpha-install.md) step 4). A public signed download is **Planned**.
- **The public entry is configured by hand.** The ICS host routes each public name to the deployment's gateway VM through nginx, and that map is
  edited by hand, again after every rebuild (the gateway gets a new address). Generated by the ICS: **Planned** (ADR-0018 G1, GitHub #23).
- `--tls-cert/--tls-key`, IPv6 and installation without internet access are not tested ([installing-the-ics.md](installing-the-ics.md)).

## Deployments
- **No in-place upgrade of a running deployment.** A new golden image, agent or app skin reaches a deployment only by destroying and creating
  it again, and a rebuilt deployment **starts empty** (accounts, mail and files are not carried over). Per-tier backup and restore exist and
  were drilled in the lab ([backup-product-results.md](../status/backup-product-results.md)) but are not wired into the rebuild.
- `deployment.change` applies resource changes (size, disks); it does not re-apply configuration or branding.
- **Certificates:** Let's Encrypt allows 5 certificates for the same set of names per week. Since 0.9.4 the ICS keeps an encrypted copy of the
  gateway's certificate and gives it back to a rebuilt gateway; verified live on 2026-11-23 (officeunbound7 rebuilt as officeunbound8: same
  certificate restored in 17 s, no new order; GitHub #24). Certificates are reused only while valid for more than 30 days. DNS-01, wildcard certificates and DNS automation are **Planned** (GitHub #25, #26).
- **Not deployed by the ICS:** chat, meetings and telephony (lab prototypes only), anti-spam and antivirus (rspamd, ClamAV: **Planned**),
  mail archiving (**Planned**).
- **Internet mail** (MX delivery in and out, SPF/DKIM/DMARC) is not verified end to end. On a deployment, webmail, ActiveSync and
  CalDAV/CardDAV answer and pass their health checks ([groupware-deploy-results.md](../status/groupware-deploy-results.md)).

## Apps and clients
- Webmail is grommunio-web with the Office Unbound look; the upstream name can still appear where the skin does not reach (texts inside
  dialogs are not rewritten).
- New Outlook for Windows and Outlook mobile cannot use MAPI/EWS against a non-Microsoft server (IMAP/SMTP only). Classic Outlook and Outlook for
  Mac are the targets, but **no real Outlook, phone or Apple client has been tested**; Thunderbird and Evolution were tested automatically
  ([client-compat-results.md](../status/client-compat-results.md)).
- Device onboarding profiles are unsigned and untested on real devices.
- Mail migration: the assessment has never run against a real Microsoft 365 or Google tenant, and the IMAP mover is lab-proven for one
  mailbox, with no calendar, contact or file migration ([migration.md](migration.md)).

## Operations
- The reference installation runs with one administrator (`ICS_APPROVAL_MODE=single_admin`, [ADR-0017](../adr/0017-single-admin-approval-mode.md)); the
  two-person rule is covered by automated tests.
- ICS controller backups (`ics-backup.sh`) are taken by hand before each change; they are not yet scheduled, encrypted or copied off the host
  ([backup-and-restore.md](backup-and-restore.md)). No HA controller; a warm standby with operator-triggered promotion exists and is lab-proven
  ([ics-recovery-and-standby.md](ics-recovery-and-standby.md)).
- Pushover and SMS alert channels cannot be enabled (ADR-0007); the webhook channel is tested locally only.
- No mailbox purge or export action; revocation gaps are listed in [users-and-access.md](users-and-access.md).
- **ActiveSync remote wipe is not device management.** `idm.user.disable` with `wipe_devices` asks **every** ActiveSync device of the user for a
  full remote wipe; depending on the phone's mail app that can erase the whole phone, including a personally owned one. It was tested only with a
  scripted client (no real phone), the device's acknowledgement is not proof of erasure, an offline device never receives it, and in
  `single_admin` mode the administrator approves it alone. Use it only on company-owned devices you intend to erase
  ([lifecycle-gaps-results.md](../status/lifecycle-gaps-results.md); planned replacement: [mobile-remote-wipe-security.md](../requirements/mobile-remote-wipe-security.md)).
